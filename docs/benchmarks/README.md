# Sherpa Bangla evaluation, JoyKeyboard 0.4.13

`sherpa-0.4.13.json` records the measurements and raw hypotheses used for the optional experimental-engine decision. No audio or model weights are committed here. Reference metadata: `tests/fixtures/sherpa-bengali.json`.

Dataset: Google FLEURS, Bengali India (`bn_in`), test split; https://huggingface.co/datasets/google/fleurs . First twelve archive entries matching the reference TSV, with no transcript-based selection. Total 157.56 seconds, 235 reference words. Every selected entry is labelled MALE; this is a small read-speech screen, not broad microphone/accent certification. Dataset revision is in the fixture manifest. Google FLEURS references are attributed to the dataset authors under CC BY 4.0: https://creativecommons.org/licenses/by/4.0/ . Model hypotheses were generated during this benchmark.

Model: https://huggingface.co/alphacep/vosk-model-small-streaming-bn ; ONNX export https://huggingface.co/csukuangfj2/sherpa-onnx-streaming-zipformer-bn-vosk-2026-02-09 at a7c3c1547450a7c546c876be9ca8a6ab54464423. Apache-2.0; full license in assets/models/SHERPA-LICENSE.txt. Model SHA-256 values and source URLs are recorded. Sherpa 1.13.8, CPU, one inference thread, greedy decoding. A four-path beam-search trial did not improve accuracy.

Scoring uses NFC/case normalization, punctuation removal and whitespace splitting; character scoring removes whitespace. No custom spelling-equivalence mapping. WER counts substitutions, insertions and deletions divided by reference words; it is not a universal percentage of correct dictation. Compound-word spacing and spelling variants can affect WER. Sherpa scored 22.13% WER / 5.84% CER versus Google 19.57% / 4.75%. The user reviewed this difference and explicitly chose an optional experimental mode, with Google still default.

`tests/sherpa_benchmark.py` accepts `--engine sherpa|google`, `--fixtures`, `--model-dir`, `--realtime` and `--output`. Prepare model files and the PCM16 fixtures under the paths in the manifest first. Model preparation is available in the app, and the benchmark can use `%LOCALAPPDATA%/JoyKeyboard/models/sherpa-bn` via `--model-dir`. PCM fixtures were decoded through the installed PyAV/faster-whisper audio helper to mono 16 kHz and saved as PCM16; paired engines receive identical WAVs. The three-clip realtime sample uses the first three manifest entries. Replays feed 100 ms chunks, collect partials while decoding, then pad 0.5 seconds and flush immediately at Stop. Fast replay times are throughput, not realtime end-to-end latency.

App memory/CPU measurements use the actual source Qt voice job in test mode, visible floating bar, fixture recorder and local pause monitor, with automatic typing disabled. `tests/sherpa_ui_probe.py` checks preview, finalization, warmed repeat, model release on engine switch, and cancellation without a second commit. No live microphone or native keyboard hook was used for this profile. Stop-to-UI measurement ends at the result callback, before external typing. Cancellation's initial coarse-clock zero means within clock resolution, not zero work. Idle percentages are short five-second process-CPU samples at Windows counter resolution. Process working set includes shared libraries; private bytes and peak resident memory are separately recorded. Compositor/GPU memory is excluded. Initial loading and warm recording are reported separately.

Host: AMD Ryzen 9 7900X, 24 logical CPUs, about 31 GiB usable RAM, Windows x64. Runtime thread limits match main.py (OpenBLAS one, OMP two); Sherpa inference uses one thread. These results do not certify low-end hardware. Model release does not unload native DLLs/shared VAD caches or guarantee a return to the pre-load footprint.
